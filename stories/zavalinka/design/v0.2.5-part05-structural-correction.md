# v0.2.5 Part 05 structural correction: `05_04_route-by-pipe-knowledge.ink`

Дата фиксации: 2026-09-03.

## Причина

Изначально `05_04_route-by-pipe-knowledge.ink` был чистым техническим router:

```ink
{ PIPE_KNOWN:
    -> pipe_preblock
- else:
    -> window_canon
}
```

При этом основная `zavalinka-decision-map.canvas` вела `attic_both`, `attic_lera` и `attic_ilya` прямо в `pipe_preblock` либо `window_canon`. Отдельного художественного события `attic_route` на карте не было.

Это создавало структурное противоречие с workflow Issue #38: для `05_04` требовались AUTHORING BRIEF, полноценный reader-facing prose и отдельная редактура, но scene-файл не владел ни одним физическим или драматургическим событием.

## Каноническое исправление для Part 05

Для Part 05 используется следующая последовательность:

```text
attic_both ─┐
attic_lera ─┼─> attic_route ── PIPE_KNOWN=true  ─> pipe_preblock ─> d11_pre
attic_ilya ─┘              └── PIPE_KNOWN=false ─> window_canon  ─> d11
```

Канонический визуальный fragment-map:

`stories/zavalinka/design/zavalinka-decision-map-v0.2.5-part05-override.canvas`

Для перечисленных выше Part-05 узлов и рёбер этот override имеет приоритет над конфликтующими прямыми рёбрами старой `zavalinka-decision-map.canvas`. Для всех остальных частей истории исходная карта сохраняет приоритет.

## Владение событиями после исправления

### `05_01_attic-both-alive.ink`

Владеет aftermath подъёма обоих героев, ослаблением давления у люка и финальным переводом внимания на маленькое торцевое окно.

Заканчивается **до физического подхода к окну**.

### `05_02_attic-lera-alone.ink`

Владеет aftermath канонической гибели Ильи, постепенным отходом Леры от удерживания люка и переводом её внимания на торцевое окно.

Заканчивается **до физического подхода к окну**.

### `05_03_attic-ilya-alone.ink`

Владеет aftermath потери Леры, удерживанием люка Ильёй и переводом его внимания на торцевое окно.

Заканчивается **до физического подхода к окну**.

### `05_04_route-by-pipe-knowledge.ink`

Владеет общим физическим переходом от уже установленного взгляда к позиции у торцевого окна:

- герой/герои проходят несколько шагов по низкому чердаку;
- пригибаются под скатом и занимают позицию у окна;
- в ливне видимость наружу плохая;
- заражённый ещё не показан и не выдаёт себя новым отдельным сигналом;
- после этого применяется `PIPE_KNOWN`.

State changes отсутствуют.

### `05_05_pipe-known-before-window-contact.ink`

Владеет **не подходом**, а ранним осознанием угрозы по ранее известной географии газовой трубы.

При входе персонаж/персонажи уже находятся у торцевого окна после `05_04`.

Текущий production prose уже начинается у окна и структурно совместим с новой границей; обязательная перегенерация prose не требуется.

`PIPE_KNOWN = TRUE` не означает `WINDOW_READY = TRUE`.

### `05_06_choice-before-attic-window-contact.ink`

Владеет D11A choices после того, как риск уже осознан в `05_05`.

Текущий production prose и runtime не меняются этой структурной правкой.

### `05_09_canonical-attic-window-contact.ink`

Владеет первым фактическим наблюдаемым контактом заражённого у окна:

- наружное приближение/металл и скобы по применимости;
- пальцы на раме;
- лицо за мокрым стеклом;
- первый удар;
- второй удар и трещина;
- третий удар.

При входе персонаж/персонажи уже находятся у окна. Не повторять подход из `05_04`.

## Runtime invariants

Не изменяются:

- `PIPE_KNOWN` создаётся только более ранними сценами;
- `PIPE_KNOWN = true -> pipe_preblock`;
- `PIPE_KNOWN = false -> window_canon`;
- `WINDOW_READY` остаётся независимым состоянием;
- `ILYA_ALIVE` / `LERA_ALIVE` определяют только reader-facing composition `05_04`, но не меняют его сюжетный route;
- `05_04` не устанавливает и не сбрасывает flags;
- choices D11A и D11B не переносятся в `05_04`.

## Жёсткий regeneration contract

### Перегенерация prose не требуется

- `05_01_attic-both-alive.ink` — существующий финальный beat остаётся правильным.
- `05_02_attic-lera-alone.ink` — существующий финальный beat остаётся правильным.
- `05_03_attic-ilya-alone.ink` — существующий финальный beat остаётся правильным.
- `05_05_pipe-known-before-window-contact.ink` — текущий prose уже начинается у окна и совместим с новой границей.
- `05_06_choice-before-attic-window-contact.ink` — текущий prose и choices совместимы с новой границей.

Не дописывать в `05_01–05_03` подход к окну: теперь он принадлежит `05_04`.

### Уже обновлено

- `05_04_route-by-pipe-knowledge.ink`:
  - AUTHORING BRIEF переписан под новую структурную функцию;
  - первичный художественный текст написан;
  - отдельный этап `Редактирование` остаётся невыполненным.

### Обязательный refresh AUTHORING BRIEF перед редактурой или повторной генерацией

- `05_05_pipe-known-before-window-contact.ink`:
  - существующий AUTHORING BRIEF считать **stale по входной микромизансцене**;
  - новый вход: живой герой/герои уже стоят у торцевого окна после `05_04`;
  - запрещено повторять подход, переход через чердак или новый первый взгляд на окно;
  - сцена начинается с соотнесения окна с уже известной внешней географией трубы;
  - текущий prose можно сохранить как базу, если отдельный редакторский pass не выявит локального повтора.

- `05_06_choice-before-attic-window-contact.ink`:
  - существующий AUTHORING BRIEF содержит устаревшие предположения о ещё не написанной `05_05`;
  - перед `Редактированием` или любой повторной генерацией заново сверить фактический production `05_05`;
  - choices, conditions, state changes и diverts не менять из-за этой structural correction;
  - текущий prose можно сохранить как базу.

### При будущем AUTHORING BRIEF обязательно использовать новую границу

- `05_09_canonical-attic-window-contact.ink`:
  - вход начинается с героя/героев, уже находящихся у окна;
  - подход к окну не повторять;
  - первое новое событие — наблюдаемый внешний контакт.
