# Шаблон заполнения сцены «Завалинки»

Этот шаблон используется для подготовки художественного текста любого отдельного `.ink`-файла в `stories/zavalinka/scenes/`.

Он нужен, чтобы разные участники писали сцены с одинаковым уровнем контекста и не ломали сюжетную логику, географию, состояния и переходы Ink.

## Как использовать

1. Перед написанием сцены открыть соответствующий узел в `design/zavalinka-decision-map.canvas`.
2. Проверить соседние сцены: откуда игрок приходит и куда может уйти.
3. Заполнить блок ниже конкретными данными сцены.
4. Поместить заполненный блок в `.ink` как `//`-комментарии перед художественным текстом.
5. После написания проверить текст по `design/ai-text-signs-full-511.md`.
6. Не переносить технические имена флагов, knot/stitch и пояснения карты в художественный текст.

Если поле для конкретной сцены не применимо, указывать `нет`, а не придумывать искусственную деталь только ради заполнения шаблона.

## Единый authoring brief

```ink
// AUTHORING BRIEF
//
// СЦЕНА:
// - ID / файл: <номер и имя файла>
// - Knot / stitch: <runtime-имя>
// - Версия production prose: <v0.2.x>
// - Источник: <узел/узлы Canvas, исходная история, предыдущая сцена>
//
// УЧАСТНИКИ:
// - В сцене: <Илья, Лера, заражённые и т. п.>
// - Кто принимает решение: <персонаж / оба / игрок от лица героя>
// - Кто выполняет основные действия: <кто и что делает>
// - Состояние персонажей: <усталость, ранение, знание, эмоциональное состояние — только если уже установлено сюжетом>
//
// МЕСТО И ВРЕМЯ:
// - Место: <точная часть посёлка / дома / комнаты>
// - Время: <вечер, ночь, относительное положение в последовательности событий>
// - Погода / свет / слышимость: <только значимые для сцены условия>
// - Географические ориентиры: <что обязательно должно совпадать с картой и предыдущими сценами>
//
// СОСТОЯНИЕ НА ВХОДЕ:
// - Что герой уже знает: <факты, которые могли быть открыты раньше>
// - Что герой может иметь: <предметы / подготовка, если они влияют на текст>
// - Значимые runtime-состояния: <FLAG / значение; только необходимые этой сцене>
// - Откуда пришли: <предыдущий knot / варианты входа>
//
// ЦЕЛЬ СЦЕНЫ:
// - Сюжетная функция: <зачем сцена существует>
// - Что должен понять / почувствовать игрок: <без навязывания правильного выбора>
// - Что сцена должна подготовить для будущего: <если есть delayed consequence>
//
// ОБЯЗАТЕЛЬНЫЕ СОБЫТИЯ:
// 1. <первый обязательный beat>
// 2. <второй обязательный beat>
// 3. <...>
//
// ДЕЙСТВИЯ ПЕРСОНАЖЕЙ:
// - Илья: <конкретные физические действия / реплики / реакция>
// - Лера: <конкретные физические действия / реплики / реакция>
// - Другие: <если есть>
// - Важно: персонажи не должны без причины знать то, чего не видели и не слышали.
//
// ВЫБОРЫ:
// - Choice 1: <естественное действие персонажа>
//   Причина, почему выбор реалистичен: <кратко>
//   Непосредственный результат: <что происходит сейчас>
//   State / переход: <изменения и следующий knot>
// - Choice 2: <...>
// - Если выбора нет: нет.
//
// РЕЗУЛЬТАТ СЦЕНЫ:
// - Что изменилось физически: <предмет, положение персонажей, состояние помещения и т. п.>
// - Что изменилось в знаниях: <новая информация>
// - State changes: <FLAG = value / counter change>
// - Следующая сцена / возможные переходы: <knot/stitch>
//
// НЕПРЕРЫВНОСТЬ И ЛОГИКА:
// - Факты, которые нельзя противоречить: <география, уже найденные предметы, предыдущие действия>
// - Что должно оставаться неизвестным: <не раскрывать будущую угрозу / скрытый факт раньше времени>
// - Предметы должны появляться физически и сюжетно обоснованно; не создавать их только ради будущего флага.
// - Последствие выбора должно вытекать из действия, а не выглядеть произвольным наказанием/наградой.
//
// ТОН И ПОДАЧА:
// - Фокус сцены: <напряжение / бытовое действие / исследование / конфликт и т. п.>
// - Сенсорные опоры: <2–4 уместные детали: звук, свет, холод, запах, поверхность и т. п.>
// - Диалог: <нужен / минимальный / нет; о чём он функционально>
// - Темп: <короткий / средний / медленный осмотр>
// - Не объяснять игроку очевидные последствия и не пересказывать карту решений языком документации.
// - Не делать каждую деталь функциональной: допустимы обычные бытовые предметы без будущего payoff.
//
// ЗАПРЕЩЕНО / НЕ ДЕЛАТЬ:
// - <конкретные преждевременные раскрытия этой сцены>
// - <нелогичные действия или знания персонажей>
// - <изменение установленной географии / фактов>
// - Не добавлять новый важный предмет, персонажа, способность, правило мира или сюжетный факт без согласования графа.
// - Не менять runtime choices, флаги и переходы только ради удобства прозы.
//
// КРИТЕРИЙ ГОТОВНОСТИ:
// - Все обязательные beats присутствуют.
// - Действия Ильи и Леры физически понятны и последовательны.
// - Choice формулируется как естественное действие, а не как описание механики.
// - Все state changes соответствуют фактически произошедшему в тексте.
// - Вход и выход сцены согласуются с соседними `.ink`-файлами.
// - Нет преждевременного знания будущих событий.
// - Текст прошёл проверку по ai-text-signs-full-511.md.
```

## Что является источником истины

При расхождениях использовать такой приоритет:

1. логика мира и факты исходной истории;
2. уже утверждённая непрерывность написанных сцен;
3. качество и осмысленность игрового выбора;
4. текущая Canvas-карта решений.

Canvas является authoring reference. Исполняемая сюжетная логика должна оставаться в Ink.

Если при заполнении шаблона обнаруживается противоречие между сценами или необходимость изменить переход/флаг, это нужно исправлять как изменение графа отдельно, а не маскировать художественным текстом.
