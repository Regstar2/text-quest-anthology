# v0.1.7 Technical Prototype Gate

## Verdict

**PROCEED WITH CONSTRAINT**

The technical architecture is ready for the `v0.2.x` content cycle, but the final device smoke pass for the new application-level navigation must be completed before Issue #9 is closed as `PROCEED`.

This is not an architecture blocker. The remaining constraint is verification on an Android device or emulator of the new `main menu -> story catalog -> selected story -> reader -> ending -> catalog` shell and the previously reported cosmetic rapid-pagination hitch.

## Evidence available at this gate

### Narrative and persistence

The `v0.1.6` vertical slice already contains automated coverage for two known `zavalinka` routes, including the delayed `PIPE_KNOWN` consequence, `BARRICADE`, save/restore around the delayed branch and distinct terminal outcomes (`e7_attic_dawn` and `e12_glass`).

`StorySession` remains the only owner of Ink session mutation and persistence. React UI does not reproduce narrative flags or branch logic.

`StorySaveRepository` remains keyed by `storyId`; restart/delete operations are scoped to the selected story only. Corrupted and incompatible saves are handled before Ink restore and fall back to a fresh session.

### Application navigation

The previous single-story application shell was removed. The application now follows this flow:

```text
main menu
  -> generated story catalog
  -> selected manifest entry
  -> StoryLoader
  -> StorySession
  -> shared reader / ending
  -> story catalog
```

The catalog is populated from `storyLoader.listMetadata()`. It does not contain a hand-written list of story IDs or duplicate story metadata.

Selecting a catalog entry passes its `storyId` to the shared `StoryLoader`. The reader and ending screens use the selected manifest metadata rather than a `zavalinka` constant.

Catalog actions are derived from `StorySaveRepository`:

- no valid compatible save -> `start`;
- compatible unfinished save -> `continue`;
- compatible completed save -> `ending`.

Unit coverage uses two fixture metadata IDs to verify that catalog save state remains independent between stories. A second production story package is not required for this gate.

### Ads boundary

The advertising boundary remains outside narrative and persistence core. `NoAdsProvider` remains available, Yandex failures remain fail-open, and story restart continues even if the ending interstitial cannot load or show.

### Architecture review

The gate explicitly checks the following boundaries:

- no `DEFAULT_STORY` or story-specific selection in the application shell;
- no `storyId === "zavalinka"` narrative/application branch;
- no Yandex or store SDK dependency inside narrative/persistence core;
- Ink/inkjs remains the only narrative engine;
- generated manifest metadata remains the source for the catalog;
- per-story saves remain the source for `start` / `continue` state.

No SQLite/backend, plugin framework, marketplace abstraction or parallel JSON narrative engine was added.

## Automated gate status for this branch

A temporary GitHub Actions run was requested for the v0.1.7 branch, but GitHub failed the job before any runner step started. No build, test or install command ran in that job, so the run is treated as **infrastructure failure / no evidence**, not as a failed prototype check.

Because Issue #9 requires successful command evidence, this document does not claim dependency installation, TypeScript, Jest or Android assembly as newly executed for v0.1.7 until they are run successfully outside that failed hosted-runner attempt.

## Manual checks still required before final `PROCEED`

The final device smoke pass must confirm:

- launch opens the minimal main menu;
- `Истории` opens the manifest-backed catalog;
- `Завалинка` starts and resumes through the shared loader/session;
- returning from reader does not delete progress;
- ending returns to the catalog and restart affects only the selected story;
- background/foreground and force-close resume remain stable;
- offline launch keeps the story playable and advertising failure does not block the flow;
- rapid page Back/Forward and a choice immediately after layout stabilization do not lose input or narrative state.

The rapid-pagination issue reported during v0.1.6 acceptance remains classified as cosmetic unless this smoke pass shows lost input, wrong page state, changed narrative outcome or a crash. A large reader refactor is explicitly outside this gate.

## Architecture freeze for v0.2.x

After the device smoke pass, the following boundaries are frozen for the content cycle:

```text
stories/<id>
  -> generated manifest
  -> StoryLoader
  -> StorySession / InkStoryRuntime
  -> StorySaveRepository
  -> shared application reader
```

Advertising remains an application boundary and must not become a dependency of story packages, Ink runtime or persistence.

The `v0.2.x` scope is limited to:

1. full Ink skeleton;
2. scene writing;
3. consistency pass;
4. literary pass;
5. content freeze.

New technical subsystems are not automatically part of `v0.2.x`. Any architecture change must be justified by a concrete blocker found while producing the actual story content.
