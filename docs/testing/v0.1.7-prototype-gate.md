# v0.1.7 Technical Prototype Gate

## Verdict

**PROCEED**

The technical prototype gate is accepted and the architecture is frozen for the `v0.2.x` content cycle.

The final Android device pass confirmed the application-level navigation and the native Yandex banner path are usable after moving the banner out of the React Native Fabric view tree. The previously reproduced `Unable to find parentView for tag ...` crash no longer blocks the gate.

## Evidence available at this gate

### Narrative and persistence

The `v0.1.6` vertical slice already contains automated coverage for two known `zavalinka` routes, including the delayed `PIPE_KNOWN` consequence, `BARRICADE`, save/restore around the delayed branch and distinct terminal outcomes (`e7_attic_dawn` and `e12_glass`).

`StorySession` remains the only owner of Ink session mutation and persistence. React UI does not reproduce narrative flags or branch logic.

`StorySaveRepository` remains keyed by `storyId`; restart/delete operations are scoped to the selected story only. Corrupted and incompatible saves are handled before Ink restore and fall back to a fresh session.

### Application navigation

The previous single-story application shell was removed. The application now follows this flow:

```text
main menu
  -> generated story catalog
  -> selected manifest entry
  -> StoryLoader
  -> StorySession
  -> shared reader / ending
  -> story catalog
```

The catalog is populated from `storyLoader.listMetadata()`. It does not contain a hand-written list of story IDs or duplicate story metadata.

Selecting a catalog entry passes its `storyId` to the shared `StoryLoader`. The reader and ending screens use the selected manifest metadata rather than a `zavalinka` constant.

Catalog actions are derived from `StorySaveRepository`:

- no valid compatible save -> `start`;
- compatible unfinished save -> `continue`;
- compatible completed save -> `ending`.

Unit coverage uses two fixture metadata IDs to verify that catalog save state remains independent between stories. A second production story package is not required for this gate.

### Reader and choices

Page mode uses a continuous reading-page cadence rather than a local per-fragment `1/N` counter. Banner scheduling therefore remains deterministic when short narrative fragments fit on one physical page.

Conditional Ink choices can remain visible while disabled. Their source text and ordering come from story metadata tags rather than application-specific branch logic, and unavailable choices cannot be sent to `StorySession.choose`.

`Завалинка` uses `contentVersion 5` for the modified Ink structure, so saves from the previous compiled structure are explicitly reset instead of restored into incompatible choice metadata.

### Ads boundary

Advertising remains outside narrative and persistence core. `NoAdsProvider` remains available and interstitial failures remain fail-open.

Interstitial cadence is every third real story restart.

The periodic banner no longer uses the React Native Yandex `BannerView`. Device testing repeatedly reproduced Fabric failures such as `Unable to find parentView for tag 666/866/872` while that native view was owned by the Fabric tree. Styling and React lifecycle workarounds did not eliminate the failure.

The accepted Android path is now:

```text
React reader cadence
  -> NativeBannerController
  -> MainActivity
  -> Yandex Android BannerAdView overlay
```

The Android `BannerAdView` is owned by the Activity and toggled with native visibility state, so Fabric does not create/remove the advertising view. The rebuilt application was accepted on-device with this path working.

### Architecture review

The gate explicitly checks the following boundaries:

- no `DEFAULT_STORY` or story-specific selection in the application shell;
- no `storyId === "zavalinka"` narrative/application branch;
- no Yandex or store SDK dependency inside narrative/persistence core;
- Ink/inkjs remains the only narrative engine;
- generated manifest metadata remains the source for the catalog;
- per-story saves remain the source for `start` / `continue` state;
- the React Yandex provider must not reintroduce `BannerView` into the Fabric tree.

No SQLite/backend, plugin framework, marketplace abstraction or parallel JSON narrative engine was added.

## Verification record

Hosted GitHub Actions could not provide evidence because the attempted runner job failed before any step started. That remains classified as infrastructure/no evidence rather than a code failure.

During local verification, the branch reached 40/41 tests after the content-version change; the sole failure was a stale `StoryLoader` assertion that still expected `contentVersion 4`. The assertion was synchronized to version 5 in commit `0cfbc5a` and no runtime defect was associated with that failure.

The final rebuilt Android application was then accepted manually after the native-banner migration. The maintainer confirmed the resulting build works and explicitly approved merging PR #25.

## Architecture freeze for v0.2.x

The following boundaries are frozen for the content cycle:

```text
stories/<id>
  -> generated manifest
  -> StoryLoader
  -> StorySession / InkStoryRuntime
  -> StorySaveRepository
  -> shared application reader
```

Advertising remains an application boundary and must not become a dependency of story packages, Ink runtime or persistence.

The `v0.2.x` scope is limited to:

1. full Ink skeleton;
2. scene writing;
3. consistency pass;
4. literary pass;
5. content freeze.

New technical subsystems are not automatically part of `v0.2.x`. Any architecture change must be justified by a concrete blocker found while producing the actual story content.
