# v0.1.7 Android device smoke checklist

This checklist is the remaining manual evidence required to turn the prototype verdict from `PROCEED WITH CONSTRAINT` into `PROCEED`.

## Application navigation

- Cold launch opens the minimal main menu.
- `Истории` opens the story catalog.
- Catalog metadata matches the generated manifest.
- Selecting `Завалинка` opens the shared reader.
- Returning from the reader goes back to the catalog without resetting progress.
- Re-entering the catalog changes the action to `Продолжить` after progress exists.
- A completed save opens the ending state rather than silently restarting.
- Ending secondary action returns to the catalog.
- Restart affects only the selected story.
- Android Back from reader/ending returns to the catalog; Back from catalog returns to the main menu.

## Choices and narrative state

- Conditional choices that are unavailable because of earlier decisions remain visible with their full original text.
- An unavailable choice is visually distinct, disabled for touch/accessibility and cannot call `StorySession.choose`.
- At the attic without `PIPE_KNOWN`, `Сразу заблокировать маленькое окно: к нему ведёт газовая труба` is visible but disabled, while `Остаться у люка и ждать, не подходя к окну` remains selectable.
- At the same attic with `PIPE_KNOWN`, the pipe/window choice is enabled and leads to the existing `e7_attic_dawn` route.
- Force-close and resume at a decision point containing a disabled choice; its text, order and disabled state must remain unchanged.

## Persistence and lifecycle

- Make at least one choice, force-close the app, launch again and resume the same decision state.
- Background and foreground the app while reading; the session remains usable.
- Complete one known route after a cold resume and confirm the expected ending is unchanged.
- A corrupted save does not create a crash loop and starts a fresh session with a recovery notice.
- The `Завалинка` package uses `contentVersion 5`; saves from the previous Ink structure are reset rather than restored into the modified choice metadata structure.

## Offline and ads

- Launch with network disabled and complete the core story flow.
- The banner is absent from the main menu, catalog and ending screen.
- Page mode uses a continuous reading-page cadence rather than only the local `1/N` subpage number. The first displayed story page is page 1; a forward pagination step advances the cadence, and a successful choice that opens the next story fragment also advances it by one.
- With short fragments that each fit on `1/1`, page mode therefore shows the banner on the third story page reached through choices, hides it on the next page, and repeats on pages 6, 9, and so on.
- If one story fragment spans several physical pages, `Вперёд` / `Назад` moves the same continuous page ordinal and the every-third-page rule remains deterministic.
- In feed mode choices 1 and 2 keep the banner hidden; choice 3 shows it; the next choice hides it; choice 6 shows it again.
- The periodic banner is not a React Native `BannerView`. React reserves only the scheduled vertical slot; Android `MainActivity` owns a direct Yandex `BannerAdView` overlay and receives visibility commands through `NativeBannerController`.
- The Android banner uses Yandex Mobile Ads SDK 8 `BannerAdSize.inline(...)` with the same 96-120 dp maximum height reserved by React. The complete creative, including its bottom edge/text/button, must be visible without clipping.
- Repeat at least three banner show/hide cycles in both reader modes. There must be no Fabric red screen such as `Unable to find parentView for tag ...` while the native Android banner appears or disappears.
- During repeated reader navigation, opening/closing the menu, background/foreground and story exit/re-entry, the banner overlay must stay aligned below the system status bar and must not intercept touches while hidden.
- Restart attempts 1 and 2 do not request an interstitial; attempt 3 does; the pattern repeats on attempt 6.
- The third-restart interstitial rule applies to both menu restart and the ending-screen restart action.
- Banner failure leaves the application usable.
- Interstitial unavailable/load/show failure does not block restart.
- `NoAdsProvider` mode remains usable for the same core flow.

The `Unable to find parentView for tag ...` crash, an incorrectly positioned overlay, touch interception while hidden, or a visibly clipped banner is a blocker for the prototype gate. Do not move the verdict to `PROCEED` until the repeated banner-cycle check passes on the Android device.

## Rapid reader interaction

The v0.1.6 manual pass reported a brief visual hitch during very fast pagination/choice interaction without state loss.

The original v0.1.7 implementation tied page navigation to full story persistence. The v0.3.0 reader hardening removes that critical-path work:

- ordinary Back/Forward changes only the canonical reader cursor;
- already committed physical pages are not remeasured or repaginated during ordinary navigation;
- `moveToPage()` exposes the target page immediately and does not wait for disk persistence;
- `StorySession.setPage()` debounces a lightweight cursor sidecar instead of exporting Ink state or serializing the transcript;
- a lifecycle flush persists only the cursor when narrative state has not changed.

Check:

- rapidly alternate `Назад` / `Вперёд` in page mode;
- choose immediately after the choice page layout stabilizes;
- confirm there is no dropped choice, wrong page after resume, wrong narrative outcome or crash.

If the effect remains visual only, keep it as non-blocking technical debt. Do not refactor the reader during the prototype gate solely to eliminate a cosmetic delay.
