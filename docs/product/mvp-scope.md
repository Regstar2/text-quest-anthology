# MVP scope

## Пользователь

Русскоязычный пользователь Android, который хочет пройти короткую интерактивную хоррор-историю без регистрации и обязательного подключения к сети.

## Проблема

Нужно проверить, можно ли за ограниченный цикл создать и подготовить к реальной публикации небольшой, законченный, технически аккуратный text-quest product, а не бесконечно развивать внутренний framework.

## Core scenario

```text
установить приложение
→ открыть библиотеку
→ выбрать «Завалинку»
→ начать или продолжить прохождение
→ читать и принимать решения
→ прошлые решения меняют доступные события
→ получить терминальную концовку
→ вернуться в библиотеку или начать заново
```

## Срок

Разработка первого MVP ограничена **14 календарными днями**:

- начало: **28.08.2026**;
- code/content freeze: **10.09.2026**;
- после freeze допускаются только release-blocker исправления и изменения, обязательные для прохождения модерации.

Если P0 scope не помещается в этот срок, функциональность сокращается. Дедлайн не переносится ради polish, второй истории или инфраструктуры.

## Обязательно (P0)

### Android

- React Native + TypeScript проект собирается воспроизводимо;
- release package имеет устойчивый `applicationId`;
- подготовлена подписанная release-сборка для RuStore;
- signing key не хранится в Git и имеет резервную защищённую копию.

### История

- одна полностью законченная история: «Завалинка»;
- история реализована на Ink/inkjs;
- все утверждённые концовки терминальны;
- ключевые ранние решения реально изменяют дальнейшие состояния/варианты;
- нет обязательной следующей главы;
- все известные основные маршруты доходят до концовки или осмысленной смерти персонажа.

### Story package

Минимальный внутренний контракт:

```text
stories/<story-id>/
├── meta.json
├── story.ink
└── assets/
```

`meta.json` содержит только данные, реально необходимые MVP: стабильный `id`, `schemaVersion`, `contentVersion`, название, описание и ссылку на обложку/основной asset при наличии.

Story package проверяется при сборке или отдельной validation-командой. Новая история в будущем не должна требовать отдельного reader screen или новой реализации narrative runtime.

### Reader

- библиотека историй;
- карточка «Завалинки»;
- экран чтения;
- варианты выбора;
- корректная прокрутка длинного текста;
- экран концовки;
- restart;
- continue/resume;
- минимальная настройка размера текста;
- базовая тёмная визуальная тема, если она не становится отдельным крупным UI-проектом.

### Сохранения

- локальный progress per story;
- autosave после значимого изменения narrative state;
- восстановление прохождения после закрытия приложения;
- safe reset;
- `contentVersion`/save-version guard для несовместимого состояния;
- повреждённое сохранение не должно crash-loop приложение.

### Реклама

Первая реализация: Yandex Mobile Ads / РСЯ.

- `AdsProvider` как граница application/infrastructure;
- `YandexAdsProvider`;
- `NoAdsProvider` для тестов/отсутствующей конфигурации;
- adaptive sticky banner сверху reader screen;
- banner не перекрывает текст или choices и не вызывает layout jump после загрузки;
- один interstitial после концовки/на выходе из ending flow;
- interstitial не показывается между обычными выборами;
- отсутствие сети или ошибка рекламы никогда не блокируют прохождение;
- development использует demo/test ad IDs;
- production IDs подключаются только в release configuration.

### Offline-first

Без сети должны работать:

- библиотека;
- чтение;
- choices;
- narrative state;
- saves;
- resume;
- endings;
- restart;
- настройки чтения.

Интернет не является зависимостью narrative core.

### Минимальная проверка

До release candidate обязательны:

- package validation;
- save → load round trip;
- минимум несколько известных маршрутов до разных концовок;
- проверка критичных флагов/условий;
- corrupted-save fallback;
- offline прохождение;
- banner layout;
- interstitial fail-open;
- Android background/foreground;
- Android Back behavior;
- установка подписанного release package на реальное устройство.

### Публикация

К 10.09.2026 должно быть готово всё, что зависит от разработки:

- signed release package;
- icon и необходимые store assets;
- описание приложения;
- privacy policy;
- корректная возрастная/контентная информация;
- production ad configuration;
- RuStore submission или готовность немедленно отправить пакет на модерацию.

Ожидание внешней модерации после 10 сентября не считается продолжением feature development.

## Желательно (P1), если P0 уже закрыт

- небольшой набор автоматических route/invariant tests;
- улучшение empty/error states;
- несколько beta readers/testers;
- GitHub release APK + SHA-256 после store-ready build;
- небольшой polishing типографики/transition без изменения core flow.

P1 не переносит дедлайн и не блокирует submission, если P0 выполнен.

## Не входит

До первого релиза не реализуются:

- вторая история;
- backend;
- user accounts;
- cloud saves;
- downloadable story catalog;
- CMS/editor;
- user story import;
- marketplace/plugins;
- achievements;
- push notifications;
- social functions;
- платные истории;
- premium/remove ads;
- subscription;
- RuStore Billing;
- второй рекламный provider;
- rewarded/app-open ads;
- сложная analytics platform;
- несколько Android stores одновременно;
- iOS/Windows/web;
- полноценная мультиязычность.

## Публикация

Первый target — **RuStore**.

Архитектура не должна связывать narrative/runtime с RuStore. AppGallery/GetApps рассматриваются после первой публикации и не являются release blockers MVP.

## Критерий успеха MVP

MVP считается завершённым, если реальный пользователь может установить release build, полностью пройти «Завалинку», получить корректную концовку, закрыть/продолжить игру без потери состояния, а отказ рекламы не ломает основной сценарий.

Финансовый доход не является критерием завершения разработки.
