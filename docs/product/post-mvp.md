# Post-MVP backlog

Этот документ хранит идеи, которые **не входят** в первый двухнедельный MVP. Наличие пункта здесь не означает обязательство его реализовать.

Любая задача может перейти в активный roadmap только после внешней проверки `v0.4.0` и явного решения `CONTINUE`/`PIVOT`.

## Контент

- Вторая независимая история.
- Третья и последующие истории.
- Дополнительные иллюстрации/музыка для существующих историй.
- Галерея открытых концовок.
- Статистика прохождения конкретной истории.
- Повторное редактирование «Завалинки» по реальным отзывам.

Новые истории не должны требовать общей сюжетной вселенной.

## Распространение

После стабильного RuStore-релиза, по очереди:

1. Huawei AppGallery.
2. Xiaomi GetApps.
3. Google Play — только при реально доступном developer account и корректном onboarding.
4. GitHub Releases как дополнительный APK mirror.

Не создавать несколько store variants до появления второго реального канала.

При добавлении нового магазина проверить:

- актуальные правила аккаунта разработчика;
- package/signing requirements;
- формат APK/AAB;
- privacy/data disclosure;
- возможность использовать существующий signing key;
- требования РСЯ к карточке приложения/placement IDs;
- необходимость Gradle product flavor.

## Монетизация

Возможные идеи только после проверки аудитории:

- отключение рекламы за разовую покупку;
- premium;
- платные дополнительные истории;
- первая/несколько историй бесплатно, дальнейшие платно;
- rewarded ad только при естественной механике награды;
- hybrid monetization.

Не делать subscription без достаточного каталога контента.

Если используется RuStore Billing или другая store payment system, сначала пересмотреть юридический статус и налоговую схему. ИП не регистрируется заранее только ради потенциальной будущей функции.

## Реклама

Потенциальные изменения:

- убрать sticky banner при негативном влиянии на readability;
- изменить частоту/placement interstitial по фактическим отзывам;
- добавить второй рекламный provider только при реальной проблеме доступности/дохода РСЯ;
- добавить ads mediation только после измеримого основания.

Не строить собственную систему динамического выбора сетей заранее.

## Reader и UX

Возможные улучшения:

- расширенные темы;
- дополнительные шрифтовые настройки;
- animation/transitions;
- accessibility polish;
- более подробная библиотека/фильтры при росте каталога;
- ending history;
- несколько save slots, если пользователи реально просят их.

## Analytics

Если данных RuStore + РСЯ недостаточно для решения о продолжении, можно добавить минимальный `AnalyticsProvider` и события:

```text
story_started
story_finished
ending_received
replay_started
```

Любой новый analytics SDK требует повторной проверки privacy/data disclosure.

## Синхронизация и аккаунты

Только при доказанной необходимости:

- cloud saves;
- user accounts;
- backup/migration между устройствами.

Не вводить backend только ради этих возможностей без реального спроса.

## Remote content

Отдельный удалённый каталог историй, скачиваемые story packages, CMS/editor, пользовательский импорт и marketplace относятся к P3.

Они рассматриваются только если встроенная поставка историй через обычные обновления приложения становится фактическим ограничением.

## Другие платформы

Возможные направления после успешного Android-продукта:

- iOS;
- web;
- desktop.

Ни одна из них не планируется автоматически. Сначала требуется подтверждённая аудитория или конкретная портфолио/продуктовая причина.
