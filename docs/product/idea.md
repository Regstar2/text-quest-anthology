# Идея

## Проблема

Большинство небольших учебных Android-проектов демонстрируют отдельные технические навыки, но редко проходят полный путь до публикации. `text-quest-anthology` должен одновременно проверить продуктовую ценность коротких интерактивных историй и дать законченный production-like цикл: мобильный UI, состояние, сторонний SDK, подпись, магазин и поддержка после релиза.

Для пользователя проблема проще: нужен короткий законченный интерактивный рассказ, который можно пройти за одну или несколько коротких сессий без аккаунта, обязательной сети и многомесячной игры.

## Пользователь

Основной пользователь первого MVP:

- использует Android;
- читает на русском языке;
- интересуется хоррором, survival и choice-driven narrative;
- готов пройти короткую историю за десятки минут;
- не ожидает сложной RPG, визуальной новеллы или постоянного live-service контента.

## Core scenario

```text
установить приложение
→ открыть библиотеку
→ выбрать «Завалинку»
→ читать
→ принимать решения
→ получить последствия предыдущих решений
→ дойти до терминальной концовки
→ при желании начать заново
```

## Гипотеза

Небольшое Android-приложение с одной качественной законченной интерактивной историей можно разработать и подготовить к публикации за 14 календарных дней, сохранив достаточно сильную инженерную часть для портфолио и не превращая проект в универсальную платформу интерактивной литературы.

Дополнительная гипотеза монетизации: ненавязчивая схема `adaptive sticky banner + один interstitial после концовки` может приносить небольшой доход, не ломая основной читательский сценарий.

## Продуктовая модель

Приложение является оболочкой для независимых story packages. Истории не обязаны быть связаны персонажами, миром или хронологией.

Первая история — «Завалинка». Её концовки терминальны; никакая концовка не обязана вести в следующую главу.

Будущие истории, если проект будет продолжен, добавляются преимущественно как контент:

```text
stories/<story-id>/
├── meta.json
├── story.ink
└── assets/
```

Это внутренний формат проекта, а не пользовательская plugin-система.

## Первая платформа и распространение

- Платформа: Android.
- Первый магазин: RuStore.
- Вторичные магазины рассматриваются только после первого релиза: Huawei AppGallery, затем Xiaomi GetApps; Google Play — только при фактически доступном developer account.
- APK в GitHub Releases может использоваться как дополнительный mirror после релиза.

Один package name и собственный signing key должны сохраняться между Android-каналами, если требования конкретного магазина не вынуждают сделать иначе.

## Монетизация

Первая рекламная реализация — Yandex Mobile Ads / РСЯ.

Размещения MVP:

1. adaptive sticky banner сверху reader screen;
2. один interstitial после завершения истории в естественной паузе;
3. реклама никогда не блокирует выбор, сохранение или переход при ошибке загрузки.

Narrative core не зависит от Yandex SDK. Внешняя реклама подключается через `AdsProvider`.

## Не входит

До первого релиза сознательно не входят:

- backend;
- аккаунты;
- cloud saves;
- удалённая загрузка историй;
- собственный CMS/editor;
- marketplace/plugin API;
- покупки внутри приложения;
- подписка;
- платное отключение рекламы;
- несколько рекламных сетей;
- rewarded/app-open ads;
- iOS, Windows и web-клиент;
- вторая история;
- сложная product analytics.

## Риски

Главные риски:

- текст и редактура займут больше времени, чем код;
- scope разрастётся до «движка/платформы»;
- одна история даст слабый retention;
- реклама ухудшит чтение сильнее, чем оправдает доход;
- проект может задержаться из-за store/release инфраструктуры;
- потеря signing key усложнит обновления;
- новая история в будущем может потребовать архитектурных изменений, если story package boundary окажется недостаточным.

Главное ограничение против этих рисков — жёсткий срок первого цикла: **28.08.2026–10.09.2026**. Если обязательный scope не помещается, сокращается scope, а не продлевается разработка.
